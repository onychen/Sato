# 按顺序扩展 Sato

每个练习都先运行 `npm run check`，修改后再验证行为。

1. **理解事件**：修改 `examples/basic.ts`，打印 `turn_start`、`tool_start`、`tool_result`、`stop`。说明为什么一次用户输入会触发两次模型请求。
2. **添加纯工具**：实现一个不使用 `eval` 的加法工具，严格验证两个有限数字，注册到 runtime。用脚本模型验证错误参数会作为工具失败回填。
3. **添加审计**：通过 `afterTool` 记录调用 ID、名称与结果是否失败。不要记录密钥或完整文件内容。验证审计失败不会破坏消息配对。
4. **理解取消**：实现一个支持 AbortSignal 的延迟工具。在首个工具运行中取消，断言后续写工具没有执行，而且历史通过 `validateHistory()`。
5. **替换模型**：实现另一个 `ModelProvider`。把协议解析留在适配器内，用本地 HTTP 模拟流验证分块、半包、失败和取消。
6. **预算实验**：把 `maxContextChars` 调小，连续运行两轮。观察旧完整回合被从请求视图移除，`history` 仍保留完整记录；再测试当前回合过大时停止。
7. **进阶：文件冲突检测**：让 read 工具记录内容 hash，edit 之前比对当前 hash。不一致时拒绝编辑，验证外部修改不会被覆盖。进一步思考跨进程检查与写入之间的竞争。

扩展并发工具执行之前，先定义哪些工具可以并发、结果如何排序、取消如何阻止剩余副作用，以及谁负责最终完整提交历史。
